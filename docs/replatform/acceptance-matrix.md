## Route scope and source anchors

- [AuthRoutes.tsx](../../explorers-earth/src/routes/AuthRoutes.tsx), [ProtectedRoutes.tsx](../../explorers-earth/src/routes/ProtectedRoutes.tsx) and [PublicRoutes.tsx](../../explorers-earth/src/routes/PublicRoutes.tsx) are the route authority for this snapshot. Desktop and mobile protected route lists currently mirror one another. Public `:username/*` routes have visibility guards; the owner `/profile` and `/recommendations/*` routes are separate private views.
- Retain `/login` and `/register` as Google entry points. Retire password-only `/forgot-password`, `/reset-password`, `/reset-link-sent`, `/email-verification`, `/email-confirmed` and password enrollment/recovery actions under 2.4. Legacy `/guides/*`, `/music`, `/hub` aliases have explicit routes and remain compatibility checks under 7.1. `/subscription-plans` and `/checkout` are current source routes but commerce is excluded by the global constraints; they are intentional removals, not broken retained flows.
- The current public `/:username/*` fallback redirects unknown paths to the username root; `NAV-03` covers that boundary. `PublicRoutes.tsx` also defines route-specific map and taxonomy variants. Public Music has both profile and share routes.
- Current Tunes route composition is [server/routes/index.ts](../../tunes/server/routes/index.ts). Its Strapi identity/public-profile gateways and optional native auth/analytics/reactivation composition are replacement seams, not a complete future API route graph. Strapi-dependent endpoints and duplicate Tunes frontend endpoints are retired by 6.1/8.1/8.2; retained Music API behavior remains `MUSIC-*`. The [migration contract](../../tunes/shared/music-migration-contract.ts) ends at `0021_explorers_analytics_receipts` in this source; target migrations are additive and not yet implemented.
- Current E2E specs in `explorers-earth/e2e` use mocks/route interception in many cases. Names in the matrix indicate useful assertions; they do not establish real API or provider parity. `playwright.config.ts` projects overlap, so select an explicit project and files. [Testing guide](../testing.md) describes separate fixture and live Music authority; no live mutation lane is part of this provisional inventory.

## Completion rule

Ticket 1.1's **current-source baseline** now has local desktop/mobile marketing screenshots and exact-head hosted validation records. Replacement acceptance remains open: each expanded scenario requires a run record against its implemented route and persona fixture, with desktop/mobile evidence where relevant and pre-existing failures classified separately. New implementation may add scenarios but must not silently remove IDs. Agent browser acceptance and owner UAT are separate evidence types.
