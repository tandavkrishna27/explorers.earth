# Unified QA delivery contract

This initial local package validates release data and nonsecret environment configuration. It does not publish, attest or deploy. Ticket 3.5 and milestone acceptance remain pending.

Use Node 24.21.0 with the locked root dependencies. `npm run platform:release -- inspect --manifest <file>` checks structure and detached digest only; its success output is `STRUCTURALLY_VALID_UNQUALIFIED`. `npm run platform:release -- verify --manifest <file> --readiness <file> --environment qa|production` currently fails closed with `TRUSTED_AUTHORITY_UNAVAILABLE`: no trusted GitHub/registry adapter exists in this package. Caller-authored proof is never accepted. No production release command exists.

The strict version-1 release manifest pins a source SHA, migration floor derived from the reviewed inventory (36), trusted repository/workflow identifiers, producer run, artifact evidence references and separate immutable API/web image digests with per-platform smoke references. Image indexes are permitted, but actual index membership, smoke execution, required checks and attestation must be independently verified by the subsequent authority adapter. Structural validity proves none of those facts. Canonical SHA-256 excludes only the root manifestDigest property; recursively sorted UTF-8 JSON rejects unsupported values. Input rejects duplicate decoded keys and unknown fields.

The QA and production JSON examples intentionally have empty origins and callbacks. They are non-deployable templates, not verified host configuration. Replace references with approved nonsecret identifiers and record the actual hostname, host architecture/version constraints, bucket and region. Do not put secret values in these documents. Names are exact secret-store references; alias resolution and real credential separation require later external verification.

One Google Web client and one private bucket may be shared. QA uses qa/ and production prod/ with distinct hosts, database identifiers/volumes and database/application secret references. Reused AWS credentials may cover both namespaces; this is application separation, not a claim of IAM separation. Validate permissions only with disposable QA objects, never production writes. AWS identity injection remains the responsibility of the later deployment adapter, not this reference mapper.

Runtime mapping uses implemented EXPLORERS_PUBLIC_ORIGIN/EXPLORERS_AUTH_SECRET and GOOGLE_CLIENT_ID/SECRET; there is no Better Auth account or separate Better Auth URL. QA runs NODE_ENV=production with EXPLORERS_DEPLOYMENT_TIER=qa and EXPLORERS_MEDIA_ENVIRONMENT=qa. Storage uses EXPLORERS_MEDIA_S3_BUCKET/REGION. Database startup requires protected MUSIC_DATABASE_PASSWORD_FILE and distinct runtime/migrator roles; do not inject DATABASE_URL. Secret resolution/protected file creation is deferred to the deployment adapter. The mapper describes runtime references and migrator password reference, not a complete deploy command.

Public configuration permits only origin, /api and /socket.io, optional restricted Maps browser-key reference and explicitly enabled public analytics identifier. No arbitrary environment map or server credential enters it. The current frontend Dockerfile still bakes VITE endpoints and runs static generation; environment-neutral build, QA noindex/canonical policy, unified compose/proxy and image smoke require the following package.

Candidate publishing must preserve all existing exact-commit required gates, including replatform-required and music-required. Red full-parity aggregates remain blockers; local delivered-slice evidence or one successful image job cannot replace them. A later trusted producer builds both images once with registry-only authority; the QA consumer uses its verified artifact and QA-only deployment authority. Production independently checks exact tested digests and QA evidence and requires the separate release decision. Never copy QA test data to production.

Outstanding operational inputs: exact QA hostname/DNS/TLS access; approved Google Web client and exact HTTPS /api/auth/callback/google; host/access/capacity verification; approved bucket/region and actual IAM boundary; environment secret presence. GitHub explorers-qa exists but its audited secret/variable name lists were empty. Local real Google signup and synthetic provider fixtures do not qualify hosted callbacks.
