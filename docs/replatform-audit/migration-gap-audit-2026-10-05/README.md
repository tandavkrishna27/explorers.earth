## Execution learnings recorded during this checkpoint

- Schema and producer coverage did not establish consumer closure: canonical identity/account APIs were present while navigation still passed the account UUID into legacy user GraphQL. Audit each seam as producer, consumer, fixture, and hosted gate together.
- Preserve identity distinctions in tests: auth user ID, canonical account ID, and session generation serve different purposes. Returning to account A needs a new verified session; reusing its old cookie is not an ABA test.
- Keep behavior when changing protocol: admitted-write confirmation failure, multi-field visibility and exact pin-order verification need canonical equivalents, not removal alongside Apollo mocks. Independent review restored seven such cases; Task1 now has29 passing tests.
- Test additions need discovery closure: adding two lifecycle scenarios requires the protected manifest and exact runner registry to grow from10 to12 together. Detect this before allocating a backend/browser run; never relax equality to accommodate the addition.
- Artifact-off does not prevent credential leakage through matcher diagnostics. Assert private cookie comparisons as booleans so both successful and failing reports remain credential-free.
- Attribute qualification precisely: the image package's supported24.21 finite186/types pass does not prove Linux child termination, full integration, image scans, or hosted success. CRLF-versus-Git-blob lock bytes remain disclosed provenance limits.
- Separate observed boundaries from hypotheses: the legacy lifecycle probe observed get-session transport failure without usable HTTP/store causality. It did not establish a general authentication or database root cause.

These are observed process corrections, not acceptance of the remaining implementation, full migration parity, or release readiness.
