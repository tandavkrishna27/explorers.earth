## Shared trace and gaps

Native core is substantial: `explorersRecommendationRoutes.ts:50` onwards binds authenticated collection/read/snapshot/membership/top-pick/entity/CRUD/order operations; `application/recommendations.ts:81` implements reorder; repository `explorersRecommendationRepository.ts:87` supports category-wide top picks and `:198` generic owned creation. All eight categories have content enums, but enums/core CRUD are not evidence of typed detail parity. Category top picks apply Books/Movies/Games/Apps/Products/People, while Places and Guides pin collections; the max15 rule must not be incorrectly applied to those collections (`frontend-feature-gap-review.md:23`).

Legacy calls are live consumers, not merely old documents: Apps/Products/People dashboard hooks above import the concrete GraphQL documents in each feature's `api/query.ts:6` and mutation files. Root `explorers-earth/src/main.tsx:32` configures Apollo transport: canonical runtime `/graphql`, otherwise `VITE_API_URL`. Removing Strapi without migrated adapters or explicitly supported facade leaves these working screens unserved. Places/linked-list and nested guide editors are independent boundaries and cannot be covered merely by migrating their parent forms.

URL-based merge remains a correctness risk when migrating manual entities: Products `utils/productHelpers.ts:79`, Apps `utils/appHelpers.ts:105`, People `utils/personHelpers.ts:111` merge presentation by URL; distinct recommendation IDs/notes must remain independently editable/removable. Owner pagination must accumulate complete category membership before top-pick/filter/count calculation; snapshot/bounded reads are implemented for finite categories, but remaining legacy category aggregate consumers require migration-specific qualification (`frontend-feature-gap-review.md:27`). Publication prompts/router state and location redirectBack are preserved behavioral obligations (`frontend-feature-gap-review.md:57`).

The current source-only countercheck inspected shared transport contracts, application catalog/recommendation/owner/public services, repository implementation and actual registered native recommendation/catalog routes. It found generic scaffolding but no typed Apps/Products/People details and no native section/claim/link operations in that bounded registration surface. This is stronger than filename/search absence, but is not proof of all conceivable plugin/runtime behavior; no deployed service was contacted.
