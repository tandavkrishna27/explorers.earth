# Frontend authentication and global-state gap review

Read-only source review against implementation-backend tickets 2.1–2.4 and implementation-features ticket 7.1. No application changes or tests executed. The backend plan covers the intended security behavior, but several existing frontend consumers are not explicitly assigned. These are additions to existing tickets, not new product scope.

## Already covered; retain rather than duplicate

- **2.1–2.2:** transactional initial account ownership, active-account authorization, separate recovery authority, canonical Music identity and no fabricated ordinary session for delegated access.
- **2.3:** ProfileForm/FeedFields, OnBoarding account decision/finalization lock, profile save/deferred-save/cross-tab behavior, useCurrentUser, media upload and profile DTO onboarding status.
- **2.4:** Login/GoogleAuthRedirect/AuthRoutes/auth store/AuthSyncManager/useLogout/settings/lifecycle services are already named. Expired/revoked sessions, cross-origin mutation, cross-tab logout, cancelled callbacks and password-route retirement are already explicit. The missing work is their full consumer inventory and executable UI-state assertions above.
- **7.1:** public gateway visibility, pagination, ETags, owner/anonymous cache reuse and public category navigation parity already have an owner. Do not move core auth bootstrap until Epic 7; the Books milestone needs it.
- `AuthSyncManager.tsx` already fences account generation and clears Music query/publication state. Carry those safeguards into the canonical identity implementation; do not keep its Strapi eligibility query merely because Music's service layer has moved.

## Test ownership and runnable harness

Existing frontend harness command is `npm --prefix explorers-earth run test:unit -- <test-file-or-directory>` (contained Vitest runner). Extend these real suites rather than claiming generic coverage:

- **2.4 guards:** `src/components/__tests__/ProtectedRoute.test.tsx`, `ProtectedRoute.lifecycle-identity.test.tsx`, `src/__tests__/ProtectedRoutes.test.tsx`; create `src/components/__tests__/GuestRoute.test.tsx` for verified-session bootstrap/redirect states.
- **2.4 session/reset:** `src/components/__tests__/AuthSyncManager.test.tsx`, `src/hooks/__tests__/useLogout.test.ts`, `src/store/__tests__/store.test.ts`, `useSetupStore.test.ts`; add delayed-response/failed-revocation cases and a dedicated shared session-boundary test if a new coordinator is introduced.
- **2.4 recovery:** update `src/pages/__tests__/Reactivate.music-transport.test.tsx` from old-server transport expectations to the accepted protocol; add page-level recovery state assertions, alongside the already planned server proof tests. Existing transport tests alone cannot prove this UI flow.
- **2.3/7.1 surfaces:** `src/__tests__/Sidenav.test.tsx`, `HeaderCategory.test.tsx`, `src/features/navigation/__tests__/CategoryNavigationProvider.test.tsx`, `categoryNavigationSurfaces.test.tsx`, `src/features/Settings/__tests__/Settings.lifecycle-identity.test.tsx`.

For each example above, pass its full `src/...` path to the command; no new command is required. Browser cases should be added to the planned `e2e/replatform` auth/profile coverage and selected by the existing planned `platform:test:e2e` wrapper's Books milestone suite. Exercise two browser contexts/tabs, reload, back navigation, deferred network response, session expiry during an open form and anonymous public navigation. These are proposed acceptance checks, not executed results. Live Google consent remains its separate environment-dependent smoke; browser fixtures must not be reported as a completed real provider login.

## Disposition

No new epic is necessary. Expand **2.3 and 2.4** with the concrete files and state transitions above; retain **7.1** as the public/navigation regression gate. The backend recovery design is covered, but its existing email-based frontend is not yet assigned to that design. Core route/bootstrap/session-boundary completion must be part of Milestone 1, not deferred to final Strapi retirement.
