## Counts, and a counting trap that has now bitten twice

- **Legacy: 11 executing cases**, not 10. Ten `test(` titles, but
  `account-lifecycle.spec.ts:218` wraps one in `for (const statusMode of ["delayed","error"])`,
  so that title runs twice.
- **Canonical: 12 executing cases.** Ten plain `test(LIFECYCLE_CASES[n])` calls plus two
  generated by `for (const returningA of [false,true])` at
  `e2e/replatform/lifecycle.spec.ts:202`.

Both undercounts come from the same mistake: a line-anchored `grep -nE "^\s*test\("`
cannot see a `test(` that follows a `for (…)` on the same line.

**And `grep -c "test("` is not the fix** — it counts call sites, not executions, so it
reports 10 for the legacy file where 11 cases run. The only reliable count is the runner's
own: `npx playwright test --config=<lane> --list`, or the "N passed" line.

Verified that way rather than asserted: `--config=playwright.lifecycle.config.ts --list`
reports **22 tests in 1 file** — 11 unique titles across two projects — which is where the
11 comes from. The canonical lane's `--list` needs `LIFECYCLE_E2E_FIXTURE_PATH` and the
disposable PostgreSQL harness, so its 12 were enumerated from the `LIFECYCLE_CASES` indices
the spec actually calls. I published the
canonical undercount as a "correction" to a claim that had been right, then wrote a bad
recipe for avoiding it; do not inherit either.

## The map

Status values mean exactly this:
- **covered** — a canonical case asserts the same property. Safe to retire *once the gating
  in (1) is done*.
- **partial** — a canonical case asserts something adjacent but not the same property. The
  named difference must be closed or accepted before that legacy case is retired.
- **gap** — nothing canonical asserts it.

## What each non-covered row actually needs

1. **`:219`, the only clean gap, and the one worth caring about most.** Its own comment says
   "Break caught: an unresolved lifecycle read leaves a destructive entry point" — it exists
   because that regression happened. It asserts that while the lifecycle read is **delayed**
   or **erroring**, no destructive control is reachable. The canonical lane has no equivalent:
   it drives faults through `control('expire')` and origin checks, never an unresolved
   *status read*. This is also the browser-side twin of the typed-observation work: `unknown`
   exists precisely so a pending or failed read is not mistaken for a decided state. **Do not
   retire `:219` without writing this case canonically.**
2. **`:248` pending deletion survives reload and a second tab.** `[2]` covers deactivation
   revoking both tabs — the opposite direction (authority removed, not state surviving).
   Needs a canonical case, or an explicit written acceptance that reload/second-tab
   persistence is covered by the server's revision reads alone.
3. **`:232`** — `[7]` proves the tombstone and denies recovery, but not that **every ordinary
   delete entry point is hidden** in the UI. Add that assertion to `[7]` and this becomes
   covered.
4. **`:282`** — the read-only property is asserted against the server. If a browser-side
   assertion is wanted, add it to `[3]`; otherwise accept the server receipt in writing.
5. **`:302`** — `[2]` proves revocation but not "exactly one command carrying the **observed
   revision**". Add a request-count and revision assertion to `[2]`.
6. **`:317`** — `[1]` proves a stale revision cannot **delete**. Deactivation is a different
   transition with its own guard. Extend `[1]` or add a deactivate arm.
7. **`:349`** — `[0]` proves a durable retry of **feedback**. The legacy case is about a lost
   **deletion** response keeping authority and reusing the key. Extend `[0]`, or add an arm.

1. Write the canonical cases for rows 1 and 2, and the added assertions for 3, 5, 6, 7.

Retiring it earlier removes the gate and replaces it with a nightly job.
