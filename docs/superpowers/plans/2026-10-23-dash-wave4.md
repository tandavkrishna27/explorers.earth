# Wave 4: WP10 Linking any list to any list Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any of an owner's lists can link to any other of their own lists (LNK-01..07), one level deep, with an optional role label used by Guides (LNK-08). Existing Places to People/Products links keep working on the new model (LNK-09). Linked lists are managed in the list's Manage tab with Attach, Detach and Undo, which fixes OWN-13. The public projection only exposes a link when both lists are publicly visible.

**Architecture:** Schema PR S3 (Wave 3, migration 0070) ships the general link table `collection_list_links`, the contract `tunes/shared/explorersListLinkContract.ts` and the repository `tunes/server/repositories/listLinkRepository.ts`. **WP10 creates none of these; it consumes them.** A link row has a **host** list and a **linked** list. Storage allows one link per unordered pair (A→B and B→A cannot both exist), so a link is shown on both lists: the host sees it as `direction:'outgoing'` (ordered by `display_order`), the linked list as `direction:'incoming'`. "One level" is a read rule that S3's `readListLinksForCollection` already applies. WP10 adds the commands (through `ExplorersRecommendationRepository.command`: idempotency receipts, account → category → row lock order, the same as `writeLocationMembership` today), the routes `POST /api/explorers/v1/collections/:id/links` and `PATCH/DELETE /api/explorers/v1/collections/:id/links/:linkId`, `linkedLists` on the editable owner read for every category (replacing `locationLink`/`linkedChildren`), a gated public projection, and the SPA: a `useListLinks` hook, a `LinkedListsSection` under the items, and a `LinkedListsPanel` in `ManageTab` with an attach picker and "Create a new list" through `NewListDialog`. Create-and-attach runs in one transaction through a new optional `attachTo` field on collection create. The Places-only pages, tabs, client methods and contract are deleted.

**Tech Stack:** Express + TypeScript + `pg` (tunes), Zod v3 contracts in `tunes/shared/`, Vitest (unit and real-Postgres integration), React 18 + TanStack Query + React Router (explorers-earth), Playwright replatform lane `place-links`.

**S3 interface (from wave 3).** Source of truth: `docs/superpowers/plans/2026-10-23-dash-wave3.md` Task S3-5 and the scratchpad `s3-interfaces.md` section 0070 (the wave 3 plan wins on conflict). Task 0 re-verifies these against merged S3 on `origin/main`.

// WP10. Result of attach/detach/role commands. 0070's triggers bump the content revision of
// BOTH categories a link touches, so the client needs both to send the next command. Detach
// returns the removed link so Undo can re-attach it with the same role and position.
export const listLinkCommandResultSchema=z.object({
 link:listLinkDtoSchema,
 attached:z.boolean(),
 revisions:z.record(listLinkCategorySchema,z.number().int().positive().safe()),
}).strict().superRefine((v,ctx)=>{
 for(const category of [v.link.hostCategory,v.link.linkedCategory])
  if(v.revisions[category]===undefined)ctx.addIssue({code:'custom',message:`Missing ${category} revision`,path:['revisions',category]});
});
export type ListLinkCommandResult=z.infer<typeof listLinkCommandResultSchema>;
