# WP5 Performance (OWN-17, OWN-19, GL-07) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the serial round trips behind slow saves and loads (movie add, place add with photos, Home), stop lists and place images silently disappearing, and prove it with before/after measurements at 185 ms injected latency.

**Architecture:** The latency is serial round trips at about 185 ms each, not query cost (root-cause doc, OWN-17). Fixes therefore remove or overlap round trips: the SPA navigates as soon as the movie create returns and finishes the image import in the background; the server copies up to 3 movie images at once with one progress write per image; Places uploads photos in parallel before the create, sends their ids on the create and refreshes the owner view once; Home observes `/me` through one query; the server writes media rows in one statement. OWN-19 adds a provider-photo fallback and an error row instead of dropping a list.

**Tech Stack:** Express + `pg` (tunes/server), React 18 + TanStack Query v5 (explorers-earth), Vitest, Playwright (Chromium CDP network throttling for the measurement), Postgres 15 for integration tests.

async function throttle(page: Page) {
  const cdp = await page.context().newCDPSession(page);
  await cdp.send("Network.enable");
  await cdp.send("Network.emulateNetworkConditions", { offline: false, latency: RTT_MS, downloadThroughput: -1, uploadThroughput: -1 });

function countApi(page: Page) {

  return { seen, stop: () => page.off("request", onRequest) };

import { toast } from "sonner";
import { explorersApiClient } from "../../../lib/explorersApiClient";
import { invalidateMovies } from "./explorersAdapter";

// The provider-image copy is its own idempotent command with a durable receipt, so the
// add page no longer waits for it: the list shows provider images until the copy lands.
export function startMovieImport(recommendationId: string, key: string) {
  const controller = new AbortController();
  const done = (async () => {
    try {
      const fresh = await explorersApiClient.getMyEditableRecommendation(recommendationId, controller.signal);
      const imported = await explorersApiClient.importMovieMedia(fresh, key, controller.signal);
      if (imported.slots.some((slot) => slot.status === "unavailable")) toast.info("Saved. Some provider images could not be copied.");
    } catch {
      toast.info("Movie saved. Provider image copying is unavailable; original images remain.");
    } finally {
      invalidateMovies();
    }
  })();
  return { done, cancel: () => controller.abort() };
}

### Task 3: Server copies movie images 3 at a time (failing test first)

**Files:**
- Modify: `tunes/server/application/movieMediaImport.ts:98-120` (the per-slot loop), `:75` (`save`)

Design (keeps every existing safety property):
- **Budget is reserved before a batch, never after.** Before starting a batch of `k ≤ 3` pending slots, one `save` increments `download` by `k` and `reserved` by `k*IMAGE` (the existing per-slot reservation, done once for the batch). The lineage checks at `:105` and `:111` run against the batch totals, so the 24-request and 60 MB caps can only be over-counted, never under-counted.
- **Phase callbacks no longer write.** `fetchOwned`'s phase callback (`dns/connect/body`) still calls `assertCurrent()` but only bumps in-memory counters; they are persisted with the image's completion write.
- **One progress write per image**: the existing `createMediaOwned(..., readyWrite)` staging write (`:113-115`) carries the slot status, the received bytes and the phase counters.
- **Writes are serialised** on the single `db` connection with a promise chain; state updates apply to the latest `progress` (functional merge by slot index), so parallel completions cannot overwrite each other.
- Alias reuse (`:100-101`) and the `unavailable` path (`:118`) are unchanged per slot.
