## Terminal deletion capability — requires independent security review

Root ruled that terminal deletion removes owned content rather than retaining editorial data through archive. `purge_explorers_account_content(account UUID, operation UUID)` is a narrowly scoped SECURITY DEFINER function with `search_path=pg_catalog,public`, qualified relation references, PUBLIC execution revoked and runtime EXECUTE granted. It locks the account, requires `pending_deletion`, a due deletion timestamp and a matching same-account `running` delete operation. It deletes owned collections/recommendations and category pin state; FK cascades remove items, pins and typed attachments. Shared catalog entities and the canonical account row remain. Active/foreign account calls fail with SQLSTATE 42501. Generic runtime content DELETE remains denied.

`accountLifecycleMaintenance` invokes that capability inside its existing finalization transaction before deleting media metadata. Existing storage cleanup and lifecycle checks stay in place. Direct SQL tests prove purge rollback, successful retry/no-op and shared/foreign content survival. A real lifecycle integration case covers nonempty collections, an empty guide collection, recommendations, pins, typed cover media and actual local object deletion, then checks account tombstone and completed operation. This adds no HTTP upload purpose; 3.2 owns that transport extension. Future companion category/guide tables must cascade from core owned rows or explicitly extend terminal purge.
