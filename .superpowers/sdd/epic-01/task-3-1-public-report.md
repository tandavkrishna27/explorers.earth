## Contract and scope ruling

- GET `/api/explorers/v1/public/profiles/:username/collections/:category` returns `{version:"explorers-public-content/v1",items:[{id,title,slug,description,heading}],nextCursor}`. GET `/api/explorers/v1/public/profiles/:username/collections/:category/:slug/recommendations` returns the same envelope with children `{id,title,kind,userRating}`. IDs are public collection/recommendation resource locators; account, entity, membership, media and receipt identifiers are not projected. No embedded child arrays, totals or implicit bulk success.
- Ruling: introduce explicit core public routes rather than adopting these DTOs as the existing public-profile contract. Current Books `api/query.ts` public/dashboard queries request Strapi fields, provider facts, rich notes, pins and media, with 100 lists/200 nested children; Movies/Games/Apps/Products/People follow the category-shaped legacy consumers. Existing canonical `/profiles/:username/recommendations/:category[/ :slug]` uses its legacy public service/contract, and its PostgreSQL gateway currently returns empty categories/no detail. These existing screens and routes remain unchanged. Core DTOs are deliberately incomplete and are not frontend parity evidence.
- No owner reads/counterpart added. No caller-selected account authority or Actor bypass introduced: the guest handle locates an explicitly public resource only. No entity resolver/provider transport/notes/details/top picks/editor metadata added.
- Every page checks active account, complete onboarding, public profile and public category. Child reads additionally require public, published, nonarchived collection and published, nonarchived recommendations with exact account/category membership joins. Hidden collection, wrong category, unavailable ancestor and missing resource return the same bounded 404 envelope; public empty category returns an empty page. Validation rejects unknown query keys (including username/category/slug/account selectors), duplicate/array values, malformed categories/handles/slugs/cursors and noncanonical limits. Only `limit` (1–24, default12) and `cursor` are query inputs. Matching is strict and case-sensitive. Cache-Control is no-store, rate limiting is 120/minute per IP. No cache or ETag can restore revoked content.
- All SQL is parameterized; handle resolves through handle_key, category through its account key, collections through ordered account/category lookup, children through collection membership. Select lists are explicit; neither rich JSON/private notes, raw objects/S3 URLs nor owner command DTOs enter responses.
- Ruling: omit media entirely. Existing `MediaRepository.isPublicAttachment` allows only profile/feed references; publishing recommendation media requires coupled delivery/revocation policy. Returning inaccessible URLs now would invent frontend parity, and weakening byte access is outside this slice. Collection/recommendation attachment byte policy and projection remain deferred together.

## Pagination and concurrency

Stable keyset order is `(display_order,id)` with `limit+1` SQL reads; only `limit` response items. Continuation uses AES-256-GCM authenticated encrypted opaque tokens, with a domain-separated key derived from the canonical application secret. Tokens bind version/order, handle, category, collection slug versus list feed, limit and resolved account, plus collection revision for children. Encryption keeps internal account/revision context out of public token plaintext. Tamper, wrong profile/filter/limit and handle reassignment fail400; no unsigned offset cursor is accepted. Secret rotation invalidates existing tokens with400 (restart). Tokens do not expire independently; all public gates are rechecked on use.

Each page runs in one repeatable-read read-only transaction. Pages are live reads, not a snapshot across HTTP requests. Child collection revision changes (including supported create/reorder/archive changes) return409 `PAGE_CHANGED` with `restart:true`, after privacy gates. A private/archived collection returns404 even with an old token. Recommendation publication/archive changes between pages are reflected immediately: hidden later rows disappear and a continuation can legitimately be empty. Collection listing is live keyset pagination; inserts/moves before the cursor may not be seen without restarting, and deletions/visibility changes disappear. No complete-set mutation consumer may use this guest feed. Owner aggregate reads, generation cancellation and page-two failure blocking complete-set writes remain a separate Actor-authorized slice.
