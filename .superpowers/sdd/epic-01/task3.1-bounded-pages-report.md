## Behavior and finite transport bounds

Normal reads obtain the decimal category revision through a constant primary-key lookup in `account_category_content_state`, in the same short repeatable-read transaction as the payload. There is no category fingerprint/hash, category JSON aggregation, legacy v1 fallback, transaction held across requests, or authority derived from a token. Every read checks Actor scope/current membership/account lifecycle/session generation and expiry before the transaction, inside it, and after COMMIT through fresh authorization.

Three literal owner GET boundaries are added, with matching unsupported-method tombstones:

- `/api/explorers/v1/categories/:category/content-snapshot` obtains the shared snapshot and pin revision.
- `/api/explorers/v1/categories/:category/memberships` returns fixed-shape membership tuples, with independent explicit active/archived/all parent and recommendation filters and an optional owned recommendation locator.
- `/api/explorers/v1/categories/:category/content-snapshot/validate` rechecks the shared revision at completion.

Combined snapshot/membership/validation reads require both named read scopes; collection/recommendation pages retain their own scopes. A snapshot token crosses all three streams by design. AES-GCM uses separate snapshot/cursor AAD domains and a v2-derived key. Tokens bind account/category/version/observed revision/issuance/absolute ten-minute expiry. Cursors additionally bind operation, every status/locator/filter, limit, ordering version and the exact immutable snapshot token. Canonical encoding, 4096-character maximum, tampering/rebinding/expiry failures, restart conflicts and no-store responses remain enforced. A new authenticated session for the same account is not rejected merely for token possession; stale Actors/sessions remain independently denied.

Pages retain default 24, maximum 100 and SQL limit+1 lookahead. Collections first return only IDs/order plus an SQL-computed exact emitted JSON byte indicator; no unbounded text is transferred at that point. The server combines those sizes with actual encrypted continuation/envelope bytes and fetches text only for the whole-item prefix which fits the 4 MiB UTF-8 budget. Boundary items fit without an arbitrary reserve, whitespace is preserved, escaped controls/multibyte characters count correctly, and the continuation resumes immediately after the last emitted item. An individual oversized legal row fails typed HTTP 413 `RESOURCE_TOO_LARGE` before its text is fetched; the shared error schema recognizes that code. Collection details use the same numeric indicator before fetching text. Rich description/note/provider JSON is never selected.

Recommendation core DTOs contain no nested membership array. Batched pin lookup is bounded by the selected IDs; lateral media lookups fetch at most 21 rows per recommendation and fail 413 on overflow beyond the existing API-supported 20. Memberships are paginated independently without a domain cardinality cap or silent truncation. Every query result is bounded by IDs/page limits; authorization and revision lookups have fixed cardinality. Legal large memberships remain fully reachable. Selected collection locators are owned/category-matched even when archived; membership feed filters explicitly determine parent archive visibility.

## Rulings and development failures

Ruling: preserve legal unbounded stored description/heading values on the owner read wire while preserving bounded mutation validators — transport bytes determine acceptance, so SQL-legal legacy rows are neither trimmed nor given a new domain cap; a wrong byte calculation would reject or over-transfer a row, covered by actual near-limit/escaped UTF-8 tests.

Ruling: use two bounded collection queries (byte indicators, then the selected text prefix) — this prevents oversized text transfer and computes exact envelope/continuation bytes; it adds one query per collection page/detail in the same repeatable-read transaction.

Ruling: add a separate selected-collection index after actual plan evidence — the previous index did not avoid the measured sort/lookups; cost is another index maintained by membership writes.

Ruling: fixture writer uses transaction-local `plan_cache_mode=force_custom_plan` for bulk scale seeding only — pg_stat_activity identified the deferred entity-kind guard INSERT as the timeout, and its existing CASE on TG_TABLE_NAME produced a cached generic whole-table scan per row. All guards remain enabled, no production function/session policy is changed, and the setting is cleared before measuring production reads. Initial fixture timeouts are not represented as passing scale evidence.

Ruling: preserve 0030/0031 in the image inventory and add 0032, repairing an existing multi-argument `toContain` assertion to independently check every listed file — the corrected test first failed on the missing historical image literals. Cost is a stricter image verification step; no compatibility/grant authority is widened.

Initial stale sidecar authority was rejected before tests and replaced by an owned attested sidecar. ## Remaining acceptance

The snapshot-validation endpoint verifies one observed committed revision; a mutation immediately afterward can invalidate it. Future complete-set writes must acquire the category lock and compare the expected category revision inside their own write transaction. Checkpoint C still needs one jointly fenced, deeply immutable collection/recommendation/membership collector, shared page/row budgets, cancellation/generation/expiry fences, final server validation and writer prerequisites. Existing separate `getAllMyCollections`/`getAllMyRecommendations` compatibility methods and UI managers are not upgraded to that contract here. Top-pick operations, UI behavior, hosted/browser qualification and full-ticket acceptance remain open.
