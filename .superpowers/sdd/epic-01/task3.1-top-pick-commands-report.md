## Implementation

The canonical RecommendationService now exposes `setCategoryTopPicks` and `upsertCategoryTopPickOrder`, both requiring the existing `recommendations:write` operation through the current Actor/session/membership/lifecycle boundary. Literal canonical PUT `/api/explorers/v1/categories/:category/top-picks` and PATCH `/api/explorers/v1/categories/:category/top-picks/order` registrations use the existing mutation/origin/query/idempotency handler. Both paths have fail-closed unsupported-method tombstones. Only books/movies/games/apps/products/people are accepted.

Strict shared input requires both safe-decimal `expectedCategoryRevision` and explicit positive-safe-integer-or-null `expectedPinRevision`, plus 0..15 unique recommendation memberships. UUIDs normalize to lowercase before duplicate detection and canonical receipt hashing. Category comes exclusively from the route/application argument. Caller account, position, completeness and other unknown fields are rejected.

PUT atomically replaces all saved pins with supplied positions. PATCH only upserts the supplied memberships and positions; omitted saved pins, legal equal positions and persisted unions above 15 survive. Empty PATCH does not remove rows; empty PUT clears. Private/draft owned parents and recommendations are eligible, and pin commands never publish them. Exact current same-account/category membership and nonarchived parent/child predicates are checked before any state/pin mutation.

Responses are bounded to the supplied rows and use explicit `operation: 'replace' | 'upsert-order'`. Replace returns the complete replaced pin set; upsert-order returns affected rows only. Neither result grants category content completeness or a snapshot token. No full-union query or truncation is introduced.

The existing command seam locks active account, checks and replays receipts before stale/membership checks, then acquires namespace 44031 category locks. The callback compares actual category revision, locks and compares nullable pin state, validates memberships, transitions pin revision exactly once and mutates pins. Absent state starts at 1, including accepted empty commands; existing state increments once. Ruling: transition pin state before pin-row DML because new pins require the existing state FK. This preserves the frozen once-per-command transition and whole-transaction rollback. Existing 0031 triggers perform all category invalidation; the response reads actual post-DML revision rather than assuming old+1. Receipt stores exactly this bounded response. Overflow, injected post-pin-DML failure and injected COMMIT failure roll back pins, both revisions and receipt.

No SQL migration, historical SQL edit, new privilege, category-counter DML or trigger bypass was necessary. Existing archive cleanup, membership cascades, lifecycle invalidation and guarded terminal purge remain authoritative. Actual command-created pins are purged through that machinery, cannot replay into a pending-deletion account, preserve shared facts/another account, and leave eight data-free category counters.

Both official generators were run. Their committed runtime inventory and authorization matrix include the two owner operations and two tombstones. The literal inventory test now independently requires those boundaries. Forbidden-authority scanners and coverage thresholds are unchanged. Frontend production code is unchanged; the existing clean sibling-validator bundle test now executes and validates the new strict command schema.
