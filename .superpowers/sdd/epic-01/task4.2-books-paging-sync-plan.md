- If ordinary action rejects because target became unavailable, only accept outcome if required row is NOW visibly present on the SAME expected route, terminal Load more control absent and no Books loading/continuation failure state. Detachment/absence alone is never success. Otherwise rethrow original action failure.
- Always execute the original final-row visibility assertion, actual row click and rich-note modal assertion. Preserve remaining category/subject/later-list/private duties without alteration.

The exception path is a proved content-outcome predicate, not a blanket catch or request retry. A current error, missing row, wrong route, pending busy state or terminal incomplete page must fail. No timeout increase, forced pointer, synthetic product events, auto Retry, broad .toPass loop or discarded errors. One normal click can still spend its existing action timeout if detachment occurs during its action; this plan does not invent cancellation or race an uncancelled pending click against a row wait. Faster cancellation requires a separately reviewed supported mechanism, not extra infrastructure here.
