## Delivered contract

- Canonical app mounts owner routes through `auth/canonicalApp.ts`, which is the actual canonical startup composition. The legacy `routes/index.ts` has no canonical Better Auth composition and was not modified.
- POST `/api/explorers/v1/collections`; PATCH/DELETE `/collections/:id`; PATCH `/collections/:id/order`; POST `/recommendations`; PATCH/DELETE `/recommendations/:id`; POST `/entities/resolve`. Other methods return 405. Static `/recommendations/search` is reserved before `/:id` and returns 405 until search is delivered. Routes use case-sensitive, strict matching; query parameters are rejected. Mutating requests require exact trusted Origin, current session Actor and Idempotency-Key. Responses use `Cache-Control: no-store`.
- `RecommendationService` independently rechecks `authorizeOperation` for `collections:write` / `recommendations:write`; `CatalogService` requires `entities:resolve`. Account authority always comes from Actor. Caller account/user IDs, entity/category reassignment and unknown keys are rejected. Existing authorizer rechecks membership, lifecycle, session generation and session existence; OAuth scope enforcement is preserved, but no OAuth transport was introduced.
- Shared runtime validators and exported input/DTO types have no server runtime imports. Collection core: category, normalized title/slug, visibility/publication, nullable plain description/heading/coverMediaId and revision. Update intentionally excludes slug/category/account changes. Recommendation core: entity/category, rating 1..10 or null, publication state, ordered unique media IDs (max20), revision. Guides are collections only; Music is excluded. Places may target place or person. Other catalog categories have the existing exact kind map.
- Explicit `CollectionCoreDto` / `RecommendationCoreDto` names identify this partial interface. These are not claimed to be complete category/frontend DTOs. Omitting editable PATCH fields preserves them; explicit null clears nullable fields. Empty patches fail. Text/revision/UUID/media/key lengths and types are bounded; there is no arbitrary JSON patch, provider facts or rich-document field.
- Existing-ID resolution returns only `{id,kind,title}` for a catalog entity reachable through the Actor's nonarchived recommendation and nonarchived collection. It validates requested category/kind and does not expose private foreign catalog context. It performs no mutation and does not need a replay receipt. Provider/manual ingestion remains an internal trusted seam; HTTP cannot create or overwrite shared facts. Entities have no archival column; eligible context is checked instead. No anonymous/public catalog resolver was added.
- Repository extends existing command transactions rather than creating another replay system. Create/update/reorder/archive retain account locking, operation/account/input-hash binding, expiry rejection and expected revisions. Archive replay is evaluated before checking the now-archived row. Unrelated stale live updates are 409; new commands against an already archived resource retain the reviewed repository's unavailable/404 behavior.
- Cover/recommendation attachment replacement occurs in the same transaction as revision and receipt. Existing FK and deferred readiness/purpose guards enforce owned, ready, purpose-compatible media and rollback invalid replacement at COMMIT. No media storage keys or remote URLs are accepted. Shared entities and other owners' recommendations are preserved on edits/archive.
