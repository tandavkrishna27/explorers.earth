## Delivered contract and authority

`tunes/shared/explorersSearchContract.ts` is DOM-free Zod v3 with strict explicit owner/public discriminants, nullable effective titles and bounded owner/public result/error DTOs. Query is boundary-trimmed, at most 200 Unicode code points/800 UTF-8 bytes, with internal ASCII controls and lone surrogates rejected. Entity selectors are at most 100 unique UUIDs, lowercased and sorted; limit defaults to 24 and caps at 100. HTTP encodes entity UUID lists as a comma-separated scalar. Unknown raw keys, repeated/array query parameters and caller scope/account selectors fail validation. Music is rejected; guides return empty recommendation pages after authorization, selected-parent and continuation checks.

`OwnerContentService.searchRecommendations` reuses its existing authorization/read/snapshot seam. Active standalone, draft and private recommendations remain available to their owner. Selected collections require collections:read and an active owned parent in the same category. Search returns recommendation ID/account/category/entity ID, canonical entity, effective title/kind/rating, publication state and revision; it fetches no notes or private media. These lean observations carry neither editable-detail registration nor category completeness.

`PublicContentService.searchRecommendations` always applies anonymous policy: active/onboarded/public account, public category, active published recommendation and an EXISTS path through a matching active/public/published collection. Multiple public parents produce one recommendation row; a private second parent does not suppress an eligible path. Entity selectors cannot enumerate unreferenced catalog rows. Public output contains only recommendation ID/title/kind/rating. `GET /api/explorers/v1/recommendations/search` precedes /:id and uses requireActor; `GET /api/explorers/v1/public/recommendations/search` has no-store and its own public rate limiter. Other methods return 405. Exact GET source/method/path entries and regenerated runtime/authorization matrices preserve the executable authority inventory; unknown sources/methods remain tombstones.

`application/discovery.ts` delegates named search and listCreatorRecommendations to these services. Owner getCollection delegates its existing ID reader; null-Actor getCollection delegates the new exact public collection-ID reader, which uses the same public ancestor gates and a bounded safe core. getCreatorProfile maps PublicProfileService.shell through PostgresPublicProfileGateway, with caching disabled and an explicit four-field ID/handle/displayName/accountType adapter. The existing profile route remains `/api/explorers/v1/profiles/:username`; configured gateway selection elsewhere remains in place. No advanced creator/overlap search or MCP registration was added.

## SQL, cursors and resource limits

Search is `plainto_tsquery('simple', query)` title-token AND against the effective title. Blank lists authorized recommendations; punctuation-only matches none. There is no prefix, substring, ranking, note, biography or provider-fact search. Absent override inherits canonical; present null clears; string overrides hide canonical matches independently per account. CASE guards combined canonical/override bytes at 8192 and JSON type/key eligibility before the text-search function. Selected stored presentation is then validated using the existing catalog/override read schemas. Malformed selected listing rows fail closed and oversized ones return 413; nonmatching malformed rows do not become searchable facts.

Read limit+1 and order `(created_at,id)` ascending. PostgreSQL `to_char(...US...)` supplies exact six-digit microsecond timestamps directly to encrypted cursors, without JS Date conversion. SHA-256 binding includes operation/version/scope/account/category/query/sorted entity IDs/normalized handle/collection/limit/order. Tokens cap at 4096 characters. Owner search reuses the category snapshot and absolute ten-minute expiry, rejecting account/filter/token changes and returning 409 for content revision changes. Creator-scoped public search binds resolved identity/category revision after current policy checks. Global public search is explicitly live, has absolute ten-minute expiry and rechecks every public gate per page; newly eligible older rows can be missed during traversal. It makes no immutable-set or global revision claim.

Search transactions use read-only repeatable-read and `SET LOCAL statement_timeout = '2000ms'`. Actual PostgreSQL query cancellation is rolled back and surfaced as typed retryable 503, including both HTTP adapters. Existing owner authority is rechecked before, inside and after the transaction. Page packing measures actual emitted JSON against 4 MiB and keeps continuation at the last emitted row. The lean 100-row/title-bounded production wire fits well below that cap; a synthetic reserved-envelope helper test reaches the unchanged actual 4 MiB limit to exercise the packing branch without weakening production DTO/title limits. Client reads reject both declared and streamed oversized bodies, validate strict DTOs and cancel on caller cancellation or owner account/session generation changes. A→B→A/late401 cannot expire the replacement session. Search never registers mutation observation authority.

Canonical facts are operationally assumed stable during owner/creator fenced traversal. This is not database-enforced entity immutability: arbitrary canonical SQL edits do not fan out category revisions. Current resolvers insert or return existing identities and do not enable refresh. Any future trusted provider/catalog refresh must invalidate every referring account/category scope before being enabled.
