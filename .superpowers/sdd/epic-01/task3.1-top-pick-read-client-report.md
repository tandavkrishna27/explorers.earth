## Result

GET `/api/explorers/v1/categories/:category/top-picks` now supports the six catalog categories through `OwnerContentService`. It authorizes both `collections:read` and `recommendations:read` against the current Actor, session, membership and lifecycle before/during/after a short repeatable-read transaction. Strict input accepts only bounded limit (default24/max100), cursor and optional shared snapshot token; account/category selectors, status filters and unsupported categories fail. All pin, parent, child and exact selected-membership predicates stay account/category scoped; current archived parents/children are excluded. No foreign private locator lookup is introduced.

The read returns bounded `items`, nullable pin revision, category revision, shared encrypted snapshot token, absolute expiry and continuation. Absent pin state stays null and is not initialized by reads. Persisted PATCH unions exceeding15 are traversed with `(position,recommendation_id)` keysets; equal positions are retained and ordered by stable ID. Encrypted cursors bind Actor account/category, operation, page limit and ordering. Shared category-state triggers make committed pin-state, pin, membership or content changes invalidate continuation. Existing snapshot expiry/current authority fences apply. No new migration or rank/domain cap is introduced.

The shared browser adapter exposes `getMyCategoryTopPicks`, `getCompleteMyCategoryTopPicks`, `setMyCategoryTopPicks` and `upsertMyCategoryTopPickOrder`. The dedicated complete collector extends the existing joint collector with the top-pick page stream, using its same request/stream/actual-byte/cumulative-byte budgets, token and revision. It verifies every pin against the joined active membership and observed pin data, checks stable order/uniqueness and pin revision, and validates the snapshot after the final data page. Page-two failure or protocol/revision/session changes return a typed failure without partial completion authority. Unsupported dedicated categories are rejected before any private read.

PUT/PATCH require an original private WeakSet-registered, deeply frozen active/all joint observation. They derive expected category revision and nullable pin revision automatically, validate explicit staged candidate IDs against current observed parent/child/membership data, and generation-fence asynchronous transport. Copies/forged markers, archived-only observations, expiry and A→B→A fail. Existing staging copies remain mutable and carry no authority. The server still independently validates revisions/current membership under its accepted command locks and receipts.

Successful PUT responses describe the complete replaced pin set; PATCH responses describe only supplied rows. The client validates operation and returned supplied identities/positions, then revokes the original observation rather than granting a complete new category/union from either reply. Conflicts revoke authority and require reload. An uncertain transport failure preserves the original observation for an identical-key/input retry while it remains current/unexpired; changed input with that key remains a server409. Returned command data is frozen and has no completion marker.
