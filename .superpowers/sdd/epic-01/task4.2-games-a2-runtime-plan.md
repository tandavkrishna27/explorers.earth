## Native/token custody and security

Exact origins: HTTPS api.igdb.com:443/v4/games POST and HTTPS id.twitch.tv:443/oauth2/token POST. GameCatalog supplies fixed A1a query; transport owns Client-ID/Bearer headers and UTF8 text body. Token form body uses URLSearchParams(client_id,client_secret,grant_type=client_credentials); secrets never in URL/log. No redirect following, proxy environment inheritance, caller headers/URL/host/agent/TLS options. Native agent is dedicated no keepAlive, maxSockets8/maxTotalSockets9, no process-global agent. Certificate validation remains enabled. No compressed response acceptance/decompression: request identity encoding, reject nonidentity Content-Encoding. Header bytes<=16KiB/max64 headers; exact JSON media type application/json with optional UTF8 charset, strict single Content-Length decimal and declared<=64KiB; all actual chunks count before retention and mismatch/truncation denies.

Register request/socket/response error+close handlers before side effects. DNS/connect/response/body deadline aborts/destroys owned request/socket; timeout event alone is not cancellation. Node ClientRequest close and response close are lifecycle signals, not response success; require complete HTTP body for successful parse. Track pending DNS callback/request/socket/response custody: no-socket request close with outstanding resolver does not free resolver/native lease; late callback or socket after cancel is destroyed and awaited. For assigned no-keepAlive socket, actual socket close plus request close and any response close/settlement closes lease; aborted/rejected response remains owned through closure. Promise resolve/reject/destroyed flag alone never refunds capacity. Missing close retains quarantine slot without replacement. Disposal/cancel outcome cannot overwrite the first body-limit/timeout error. Cleanup has bounded caller wait and eventual rejection handlers, no unhandled rejection.

Token JSON strict exact fields access_token(tokenASCII1..4096), token_type case-insensitive bearer, expires_in integer31..86400; optional provider scope string[]<=32 each<=100, no credential extras. Cache expiresAt=receivedAt+expires_in*1000-30000. Server-owned expiry, no caller hint/override. Refresh flight publishes only valid token after native body success, drops raw/parsed references; old token never reused after expired/401. Cancellation detaches individual waiter; shared refresh remains while another admitted waiter exists. Last waiter cancels native request but retains singleflight/native/memory until settlement. 401 invalidates ONLY the matching token generation; never clears a newer refresh token. No hidden refresh/retry of failed catalog request: explicit next call may refresh once. 429 has fixed rate error, bounded decimal Retry-After1..60; invalid/date/duplicate Retry-After omitted. Other statuses/network failures fixed unavailable; malformed/oversize/duplicate/UTF8 errors fixed invalid-response. Failed token never returned in result or stringified error; synthetic sentinel scans all DTO/error/diagnostic output.

## Cursor, failure and replay algorithm

1. Parse strict A1a search input, attach bounded caller lease/deadline, authorize current Actor and bind account/user/credential/generation. New search reserves account execution and rate; cursor lookup checks binding+normalized query+limit+expiry before work. Cursor token random24bytes base64url; no raw account/query embedded. No cross-account/session/epoch replay even same account.
2. One lineage carries mutable attempt/scan counters and immutable accepted state. Token entries refer to that lineage; retired cursor state remains only for immutable completed receipt until TTL/LRU. Input cursor flight singleflight; each waiter separately admitted/revalidated and abortable. Existing flight is not cleared at caller timeout; true settlement owns release. New search commands have no command key/idempotency claim; cache replay only for an existing opaque cursor. Returning mutable arrays cannot mutate other callers/cache.
3. Tentative clone offset/seen/pending/results; failed attempt permanently increments lineage attempt before native start, accepted raw scans include duplicates/failed projection once known. Invalid oversized parsed page rejects; no raw-scan refund. State offset/seen/nextCursor commits only on success. Retrying same cursor after provider failure reruns same accepted offset with spent budgets; no skipped page. A failure is not cached as successful receipt. Completed cursor replay has no I/O and returns identical items/nextCursor/expiry after fresh authorization.
4. Consume pending rows preserving original order; dedup canonical numeric provider ID, no owner recommendations dedup claim. Fetch fixed offset0..5976. Earlier nonempty short pages are not proof of exhaustion: only an empty accepted page terminates. Four attempts/call can yield a valid empty nonterminal result and opaque continuation after duplicate-only pages; UI must not equate empty items with exhaustion. Pending rows must be carried exactly; one raw page<=24. Repeated identical pages cannot loop beyond explicit attempt/scan caps.
5. Boundary table: attempt249 nonempty may deliver and continue; attempt250 empty succeeds/exhausts; attempt250 ANY nonempty (including1/23rows/duplicates) fails whole CURRENT call GAME_CONTINUATION_LIMIT with no partial publication/tentative commit; attempt250 failed returns its actual provider error and terminal spent-budget lineage. Next request with spent250 fails limit before I/O;251 never issued. Earlier already delivered pages remain valid. No `nextCursor:null` manufactured at nonempty cap. Resolve has one catalog start and no search cursor/budget association.
6. Authorize after token wait, immediately before every catalog native start, after native outcome, before publication/cached replay return. Binding change fails closed; expiry during I/O410, tentative result discarded; native custody persists. No successful cache publication after last waiter abort/account suspension. Before atomically installing new entry/receipt reserve exact cache+return copies and true LRU space; cannot evict inflight/pinned entries. Old completed cursor response remains immutable even when future continuation fails. Fairness comes from no queued provider starts, peraccount oneexecute and bounded sliding rate, not an invented scheduler.

## Implemented finite interface/accounting clarifications for source review

Within the four new modules, ProviderTransport.catalog receives optional internal CatalogHooks {beforeStart:()=>Promise<void>,onStart:()=>void}. beforeStart revalidates fresh Actor after token wait; onStart spends lineage page only after actual catalog admission (token failure before catalog creation spends no page). Fixture transports model those hooks, not a fabricated start. All catalog/token/cache expiry reads use the coordinator-owned clock, never a second transport clock.

Shared execution has its own bounded15s lifetime and admitted waiter refcount. A caller abort detaches only that waiter; last detach aborts execution, while native/auth settlement owns account/memory/cache pins. Cached token memory has private retained representation reservation until observed expiry/replacement/matching-generation401. Public diagnostics still omit credentials/token/fingerprint.

Canonical state cloning conservatively reserves4MiB plus three2MiB representation allowances (=10MiB stage) before work, independently from native4MiB/body/token reservations and cache/return clones. More concurrent requests may honestly deny capacity. Each opaque state/receipt entry is subject to128process/fouraccount LRU and2MiB total; older replay entries may be evicted410, never guaranteed10min retention. Session lineage attempt counters remain shared across retained entries. This stricter bounded receipt retention preserves existing evicted/expired410 semantics; it does not silently bless unbounded replay. Native no-keepAlive `agent:false` avoids process-global agent/proxy configuration and relies on coordinator8catalog+1token custody instead of a redundant dedicated-agent connection pool.
